# rubevy documents

The layout every repository of the organization uses is described in
[sabiruby/.github/CONTRIBUTING.md](https://github.com/sabiruby/.github/blob/main/CONTRIBUTING.md).
This repository is small, so its documents sit flat here; the worklog and the verification records
have their own directories (`docs/verification/` is where a measurement of the crate lives — what
a machine carries, and what a change made of it — beside the tests that check behaviour).

What changed in each release, with the commit behind every claim, is
[`../CHANGELOG.md`](../CHANGELOG.md) at the root of the repository.

## Working on this repository

* **Do not run `cargo fmt`.** There is no `rustfmt.toml` here and the code is laid out by hand —
  the line breaks are where they are because of what is being said, and the rustdoc paragraphs
  are wrapped to read. `cargo fmt` therefore rewrites nearly every file, and a change whose diff
  is the whole crate cannot say what it did. Match the width and the folding of the code around
  what you write. (`cargo clippy --workspace --all-targets` is used, and carries two standing
  warnings: `collapsible_if` in `src/lib.rs` and `type_complexity` in `examples/headless.rs`.)
* **`.rb` and `.mrb` are both committed.** After changing any `.rb` under `src/` or `assets/`,
  run `tools/compile_scripts.sh` (the reference `mrbc` in Docker) and commit the `.mrb` beside
  it. `tests/embedded_host.rs` has one check that the two still agree, and it can only see what
  it asks.
* **Every number added to the crate gets a line in [`numbers.md`](numbers.md)** — what it is,
  where an app changes it, and where it came from, or that nobody knows.
